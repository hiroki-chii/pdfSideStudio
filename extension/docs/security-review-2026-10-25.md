## 結論

最優先は、削除・分割で除外したページの内容が出力PDF内に残る問題です。実際の `buildPdf()` を使い、表示上1ページの出力から除外した2ページ目の文字列を回収できました。

| ID | 重要度 | 問題 | 確認状況 |
| --- | --- | --- | --- |
| S1 | 高 | 内部リンク経由で除外ページの内容が出力に残る | メモリー内で再現 |
| S2 | 高・条件付き | Vite 8.3.2の開発環境に既知のコマンド実行問題 | npm audit・公開情報・同梱コードを照合、攻撃実行なし |
| S3 | 中 | 圧縮PDFの展開量・処理時間を制限していない | 65,580バイトから64MiBの展開を再現 |
| S4 | 低 | 印刷失敗・中断後に文書画像がIndexedDBへ残る | コードと既存の異常系テストで確認 |

重要度はアプリの用途に基づく調査上の評価です。S2は依存パッケージの評価と成立条件を併記しています。今回は調査のみで、アプリ本体・依存バージョン・配布ZIPは修正していません。

## S1：除外ページの情報残存（CWE-200）

- 対象：`src/pdf.js:288`。保存とZIP分割の両方が同じ `buildPdf()` を使います（`src/app.js:638`、`src/app.js:649`）。
- 条件：残すページの内部リンク注釈 `/Annots` の `/Dest` が、除外するページを参照しているPDF。悪意あるスクリプトは不要です。
- 原因：`output.copyPages()` がページ辞書から参照されるオブジェクトを再帰コピーするため、リンク先ページの内容もコピーされます。出力のページツリーに追加されないため、通常のページ数・プレビュー確認では気づけません。
- 再現：2ページ目に識別文字列を配置し、1ページ目から2ページ目へのリンクを設定。1ページ目だけを保存すると、`getPageCount()` は1ですが、出力のストリームを展開すると2ページ目の識別文字列が残っています。
- 影響：機密ページを削除して配布した場合や、1ページずつ分割して配布した場合に、受取人が除外ページの情報を取得できます。一般的な墨消しの問題とは別で、ページ単位の除外でも発生します。
- 修正案：コピー前にページ項目と参照先を検査し、不要な注釈・アクション・除外ページへの参照を除去するか、必要なページ内容だけを許可リストで再構成します。元の編集中PDFを直接変更せず、出力専用のコピーを使います。コピー後に `/Annots` を消すだけでは、コピー済みの内容が出力コンテキストに残るため不十分です。
- 回帰確認：ページ数だけでなく、除外ページの固有文字列・画像・参照オブジェクトが出力内に存在しないことを検証してください。

## S2：開発用Viteの既知の脆弱性

- 対象：`package.json` の `vite: 8.3.2` と `package-lock.json`。インストール済みバージョンも一致しています。
- `npm audit --json` はViteをhighとして検出。Windows上のファイル存在確認の迂回と、引数中の `%` の扱いにより、攻撃者が制御するファイル引数がシェルコマンドへ到達する条件でOSコマンド実行につながります。
- 実装確認：インストール済みViteの `dist/node/chunks/node.js` に該当する引数処理と `/__open-in-editor` ミドルウェアが存在します。開発サーバー起動中にこの機能へ攻撃入力を到達させられること、エディター等の実行条件が必要です。実際のコマンド実行や到達経路の攻撃検証は行っていません。
- 適用範囲：配布済みChrome拡張の実行時にはViteは動作しません。`npm run dev` は `127.0.0.1` に限定されていますが、ローカルバインドだけを理由に既知の問題を放置することは推奨しません。
- 修正案：Viteを少なくとも8.3.3以降へ更新してロックファイルを再生成し、監査・テスト・ビルドを再確認します。監査が提示した更新先は8.3.5でした。
- 出典：[Windowsでの存在確認迂回（CVE-2026-112942）](https://github.com/advisories/GHSA-587h-7wmj-h5pm)、[Windowsでの引数処理（CVE-2026-112943）](https://github.com/advisories/GHSA-698v-4r3x-3vcv)。

監査はViteに計6件のアドバイザリを関連付けています。カスタムミドルウェアでのスクリプト実行、非Windows環境の特定パス条件によるファイル公開、特定エディターとWSLでの引数解釈などは、現在の設定で成立すると確認できていないため、独立した確定脆弱性として数えていません。

## S3：圧縮PDFによる資源消費（CWE-400）

- 対象：`src/app.js:539`〜`545`。50MiBの入力制限はありますが、`PDFDocument.load(bytes)` の展開後サイズ・オブジェクト数・処理時間の上限はありません。ページ数の確認もパース後です。
- 原因：pdf-libのオブジェクトストリーム読み込みで圧縮データを展開します。PDF.jsのWorkerとは別に、この初回パースはUI側で行われます。
- 再現：固定64MiBの空白を含む合成オブジェクトストリームを圧縮し、65,580バイトのPDFを作成。`PDFDocument.load()` が1ページとして受け入れ、64MiBのデータを展開しました。初回計測の追加ArrayBuffer確保は67,045,804バイト、追加RSSは67,665,920バイトでした（実行環境・GCで変動）。
- 影響：入力サイズ制限内のPDFでも大きなメモリー消費を起こせます。さらに大きな展開量や複雑な構造では、UI停止・メモリー不足・未保存編集の喪失につながる可能性があります。
- 修正案：初回パースと出力処理を終了可能な専用Workerへ移し、処理時間上限とキャンセルを設けます。展開量・オブジェクト数・画像ピクセル数の制限も必要です。Worker化だけではプロセス全体のメモリー不足は防げません。
- 検証の限界：合成入力はpdf-libの初回パースで確認しました。ブラウザーを実際にクラッシュさせる試験や、Chrome/PDF.jsでのその後の描画は行っていません。64MiBを超える試験も行っていません。

## S4：印刷データの永続残存（CWE-459）

- 対象：`src/print-job.js:20`〜`36`、`src/print.js:12`〜`27`、`src/app.js:627`。
- 動作：印刷用の全ページPNGをIndexedDB `pdf-side-studio-print` の `jobs` へ保存します。印刷タブが全画像の読み込みを終えた後でのみ削除します。
- 残存条件：印刷タブを読み込み前に閉じる、ブラウザーが終了する、画像の `decode()` が失敗する場合。タブ作成自体が失敗した場合は呼び出し側に削除処理があります。
- 原因：1時間より古いジョブの削除は、次の `storePrintJob()` 実行時にしか行いません。時間の経過だけでは削除されず、再び印刷しなければ残り続けます。読み取り側にも期限検査はありません。
- 影響：文書画像がブラウザープロファイルへ保存され、プロファイルへアクセスできる人やバックアップに残る可能性があります。通常の他サイトから読み取れることは確認していません。READMEの「編集中の内容はメモリー内だけ」という説明とも不整合です。
- 修正案：可能ならメモリーでの引き渡しへ変更します。永続保存が必要なら、読み出しと同時の消費・異常終了時の削除・起動時の期限切れ削除・読み取り時の期限確認を実装し、保存の事実を説明します。厳密にメモリー内限定を保証するにはIndexedDBへの保存を避ける必要があります。
- 既存 `tests/print.test.mjs` の画像エラーのテストも、削除が呼ばれない現在の動作を確認しています。

## 補足：出力PDFのアクション引き継ぎ

S1と同じ再現で、ページを開く際の `/AA /O /JavaScript` も保存後に残ることを確認しました。この調査では無害なコメント文字列だけを格納し、実行していません。PDFビューアーの設定・実装次第でアクションの扱いは変わります。このアプリ内でJavaScript実行できるという結果ではありませんが、保存はPDFの無害化処理にはなっていません。安全化した出力を提供する場合は、アクションもコピー前の検査対象にしてください。

## 依存監査と有効な防御

- `npm audit --json`：脆弱なパッケージは2件（high 1、moderate 1）。コマンドの終了コード1は検出ありを示しています。
- `fflate 0.8.2`：不正なZIP64を `unzipSync()` で展開する際の無限ループが検出されました。ただしアプリは `zipSync()` による出力のみで、外部ZIPの取り込みはありません。現在のアプリ経路での悪用は確認していません。予防的には0.8.3以降へ更新してください。[公式アドバイザリ](https://github.com/advisories/GHSA-px8p-9vwx-vf98)
- `pdfjs-dist 6.3.289`：今回のnpm監査では検出なし。2024年の任意JavaScript実行は4.2.67、2026年の問題は6.2.108で修正済みとされています。現在のバージョンはこれらの修正後です。[2024年の公式情報](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq)、[2026年の公式情報](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j)
- Manifest V3、要求権限は `sidePanel` のみ。ホスト権限、外部メッセージ受付、公開Webリソースの設定はありません。
- CSPはスクリプト・Worker・通信先を自身に限定。PDF.jsは `isEvalSupported: false` で呼び出しています。
- ファイル名・エラー・文書テキストは `textContent` 等で表示。確認した `innerHTML` はコード内の固定SVGのみで、入力から到達するDOM XSS経路は見つかりませんでした。
- アプリ独自の外部送信処理、埋め込み認証情報は対象コード中に見つかりませんでした。通信の動的監視は未実施です。
