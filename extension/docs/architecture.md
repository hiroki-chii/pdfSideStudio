# 構成とセキュリティ境界

## 画面と編集状態

- `src/app.js`：画面イベント、ツール切り替え、ページ・注釈の選択と編集の調整。
- `src/model.js`：不変のページレコード、Undo／Redo、ページ数上限、ファイル名処理。
- `src/pdf.js`：注釈のレイアウト、座標変換、Canvas描画。既存テスト・利用箇所向けに出力関数を再公開。
- `src/text-format.js`、`src/text-editor.js`：文字・背景の書式モデルと、プレーンテキストとしての入力。
- `src/theme.js`、`src/fullscreen-preview.js`：配色と一時プレビューの独立した制御。

## 入出力

1. `src/pdf-source.js` がファイルの種類・サイズを検査し、専用Workerで構造を検証します。成功後に同梱PDF.jsでプレビューを開きます。
2. `src/pdf-processor.js` が操作ごとのWorkerを作成し、タイムアウト・異常終了時にも必ず終了させます。元バイト列は画面側で保持し、Worker失敗後も既存の編集状態を保ちます。
3. `src/pdf-worker.js` がメッセージを受け、`src/pdf-jobs.js` に読み込み・結合保存・ZIP分割を振り分けます。
4. `src/pdf-security.js` がパース前後の資源制限を適用します。`src/pdf-export.js` が選択ページの許可された項目とリソースを新しいPDFへコピーします。
5. `src/raster.js` が追加注釈と印刷画像を作成し、成功・失敗どちらでも一時Canvasを解放します。`src/download.js` が保存の開始とBlob URLの解放を担当します。

PDFのアップロードや外部サーバー処理は行いません。入力・出力のWorker、PDF.js、CMap・フォント・デコーダーは配布物内にあります。Manifestの権限は `sidePanel` のみで、CSPの通信先は自身に限定します。

## PDFパーサーのアダプター

pdf-lib 1.17.1には展開量の制限を注入する公開APIがないため、公開エクスポートされている低水準パーサーを、インスタンスごとに制御しています。ライブラリのプロトタイプや `node_modules` のソースは変更しません。

- 各フィルターを1段ずつ展開し、次のデコーダー構築前にバッファ制限を設けます。
- 圧縮オブジェクト・相互参照ストリームも、制限内に展開した内容だけを内部パーサーへ渡します。
- 制限超過を「不正オブジェクト」として回復して読み進めることはしません。
- ページツリーの循環・親子参照の不整合、異常な画像サイズ・予測フィルターの行サイズを拒否します。
- 全処理の待ち時間はWorkerの終了によって制限します。

バージョン依存部分はこの1ファイルへ隔離しています。pdf-libの更新時は、圧縮オブジェクト、通常／圧縮相互参照表、多段フィルター、画像、循環構造、同梱Workerの回帰検証を必ず実施してください。設定値は `src/limits.js` に集約しています。

## 出力の範囲

保存は元ページ辞書の丸ごとコピーを避け、用紙領域・リソース・コンテンツ等だけを出力します。ページ・ページツリー・カタログ・アクション・添付ファイルへのリソース参照も引き継ぎません。コピー前に除外するため、不要な内容がいったん出力コンテキストへ登録されることを防ぎます。入力PDFのページ辞書は変更しません。

この処理は一般的な墨消しや、任意の隠しデータを除去する完全なPDF無害化ではありません。選択したページ自身のコンテンツや共有リソースに含まれるデータは保持します。元の検索可能な文字・ベクター図形は維持し、追加注釈だけをPNG化します。

## 印刷データ

`src/print-job.js` は同一オリジンの `BroadcastChannel` を使います。編集画面がメモリー内でジョブを保持し、印刷タブの要求へ一度だけ応答して解放します。未取得ジョブも60秒で解放し、編集画面終了時に待機を終了します。印刷タブの復号・画像読み込みが失敗しても、永続ストレージに文書は残りません。

旧版のIndexedDB `pdf-side-studio-print` は起動時に削除します。旧タブによって削除がブロックされた場合は、画面にエラーを表示し、再読み込みを案内します。表示モードの設定だけは引き続きlocalStorageへ保存します。

## 検証

- `npm run check`：全アプリ・ビルドスクリプトの構文検査と、アプリの未定義変数・未使用参照等のESLint検査。
- `npm test`：既存の編集・画素比較と、セキュリティ・入出力・Worker・印刷の回帰検証。
- `node --expose-gc --max-old-space-size=256 scripts/security-review.mjs`：当初の情報残存と64MiBの圧縮入力の再検証。
- `npm run build`：ビルド、同梱資産・ライセンス・ZIP生成、配布Workerの実行、ManifestとZIPの一致検証。
- `npm audit`：依存関係の既知の脆弱性の確認。

実ブラウザーのサイドパネル、ファイル選択・印刷ダイアログは別途動作確認が必要です。Workerの統合テストはNode.jsのWorkerへWeb WorkerのメッセージAPIを接続して実行するため、Chromeの実行環境そのものを再現するものではありません。
